# Engineering architecture

## Scope & quality gates

- Platform: iOS 17+ (primary verification target iOS 27.0.1), SwiftUI, guest IPA for LiveContainer; code editing from Windows 11.
- Xcode project is generated by deterministic `tools/generate_xcodeproj.py`; no XcodeGen, CocoaPods, hosted backend or Apple developer account is required for compiling an **unsigned** device IPA.
- Build and runtime are separate acceptance criteria. GitHub Actions (`xcode-27`) compiles arm64 device code; only testing on the actual iPhone validates LiveContainer compatibility.
- Swift Package core compiled/tested on Linux/Windows-compatible Swift where possible. Apple UI and system service code compile on a GitHub-hosted macOS arm64 runner.

## Module boundaries

```
Sources/App/       SwiftUI screens, @MainActor UI state, Apple platform adapters
Sources/Core/      pure domain operations and actor-isolated SQLite storage
Tests/             deterministic isolated core tests
Config/            machine-readable name/version/build
Assets.xcassets/   app icon and other static assets
.github/workflows/ CI, manual IPA package and automatic release
```

### Guidelines

1. Views never execute raw SQLite statements or read arbitrary unrelated app data. Use view models and explicitly defined services.
2. Core algorithms should avoid UIKit/SwiftUI for portable unit testing.
3. DB changes require explicit migrations, tests, and a backwards-compatible backup strategy. Parameterize all query values.
4. User text/audio is private. No automatic logging, analytics, plaintext secrets or network transfer by default.
5. Every UI state includes empty, error, loading and success variants. Tap targets >=44 pt, Dynamic Type, VoiceOver labels, support light/dark.
6. Keep LiveContainer permissions assumptions minimal: no global clipboard interception, no guaranteed background jobs, no arbitrary audio capture from other apps.
7. Prefer Apple frameworks before third-party libraries; review licenses and model sizes.
8. Avoid force unwrap on imported or untrusted content; bound processing time/size, support cancellation.
9. Check iOS 27 SDK compatibility and runtime on device for platform APIs rather than treating a Linux parser or source test as proof.

## Continuous delivery contract

### Local data lifecycle

SQLite schema version 1 adds `media_trash` and `transcription_checkpoints` without rewriting existing media or segments. The migration is transactional and additive: a v0 database upgrades in place, and older builds can still read the original tables. Before manually downgrading, export important transcripts; older builds do not understand trash or pending checkpoints. Media metadata uses an UPSERT to preserve child transcripts. Subtitle replacement and checkpoint removal commit in the same transaction, so a failed replacement restores the previous transcript and pending job.

Speech checkpoints store the selected language, next chunk offset and completed phrases independently of the published transcript. Importing subtitles clears the pending job; speech publishes its staged phrases only after successful completion. The immutable local media copy is the checkpoint's source. Moving a recording to trash hides it from library/search but keeps the file, transcript and checkpoint until explicit permanent deletion. Search normalizes Unicode in SQLite using the same rule as the in-recording filter, while binding and escaping the query literally.

`MediaFileImport` performs bounded stream copies and subtitle parsing away from the main actor. `MediaViewModel` permits one import/transcription operation at a time and cancels it on background entry. Apple recognition retains its task, serializes completion on the main actor, and has cancellation and a 90-second per-chunk response timeout. `MediaPlayback` owns the player/time observer and saves position per recording.

- Work on `feature/*` / `fix/*`. AI coding agent creates commits only when it has actual working tree and Git permissions; never hallucinate commits or GitHub releases.
- `feat:` -> SemVer minor; `fix:` / `perf:` -> patch; `!` or `BREAKING CHANGE:` -> major; non-release types do not bump.
- CI runs core tests plus unsigned arm64 iOS build for changes; developers must not declare a build successful unless the Actions job passed.
- After a `feat`/`fix` lands on `master`, `auto-release.yml` creates a versioned release branch, bumps version/build and changelog, runs tests, builds IPA, checks Mach-O ARM64, publishes GitHub Release, fast-forwards into master, then deletes release branch.
- Protected branch cannot be force-pushed or bypassed; fallback opens PR, which may require approval. Token policy, GitHub Actions permissions, quota and repo settings must be configured by owner.
- A repository's `GITHUB_TOKEN` pushes generally don't trigger other push workflows. The release workflow therefore explicitly performs tests/build/publish, without relying on a chain triggered by its own commits.
- No secret keys or credentials committed. For personal unsigned IPA the project uses `CODE_SIGNING_ALLOWED=NO`; LiveContainer signing is done independently.

## Definition of done

- Behaviour and edge cases covered by core tests.
- Release scripts and generated Xcode project deterministic.
- All GitHub workflows pass on cloud Xcode; IPA uploaded and passes `verify_ipa.py`.
- Smoke test on iPhone in LiveContainer: import, launch, permissions, main operations, relaunch with persistent data, app switch, interruption, database recoverability.
- Update `CHANGELOG` via automated release and keep docs in sync with actually implemented functions.
